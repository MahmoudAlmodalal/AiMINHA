## Migration mechanics and safe rollout

For a fresh empty database, create ordinary unique indexes before exposure; install CHECKs, immutable-field guards, transition guards and deferred cross-table constraints before app privileges. PostgreSQL partial UNIQUE indexes are immediate; Django's ordinary model validation cannot substitute. Required uniqueness (grant/debit/finalization) must never rely on an application pre-check. CHECK each VARCHAR lifecycle against its enumerated matrix. Add every uncovered child-FK index (R05), including owner-prefixed tuples.

For a later populated deployment, use expand → compatible readers/writers → audited bounded backfill → constraint validation → switch → contract. Use NOT VALID only for supported CHECK/FK cases with immediate new-write enforcement; UNIQUE/partial/exclusion constraints require a separate duplicate/overlap audit and compatible build strategy. `CREATE INDEX CONCURRENTLY` is non-atomic, needs appropriate migration handling, and failed invalid indexes must be detected before granting writes. Never “backfill” guessed scholarship dates, consent, source/provider approvals, profile facts or successful credit results. A counter mismatch freezes the affected workflow and is reconciled against journal/immutable operation evidence; do not rewrite history to make a check pass.

Do not disable RLS or triggers for app convenience. Validate policies under actual non-owner roles and pooled session context, not the migration owner. Backfill requires explicit owner scope and an audited narrow role. Erasure must be designed against approved retention and versioned Admin recovery policy/ADR0008 legal envelope first; do not install broad cascading deletes on an existing journal/history graph. Staged object pointers become readable only after the complete DB acceptance transaction.

Queue schema versions and worker releases must remain compatible: pause new claims/egress if required, drain or reconcile existing DISPATCH_INTENT/UNKNOWN calls, retain IDs/fences and deploy compatible readers before new writers. Never reset lease tokens, drop unknown allocations or clear reservations to simplify migration. Rollback an incompatible application by stopping affected feature flags and preserving the newer evidence schema, then use a reviewed forward fix. Do not reverse/drop populated ledger, consent, version or event tables as an automatic rollback. Verify backup restore plus deletion/revocation replay in an isolated environment before release.
