## Protocol

JSON UTF-8 under `/api/v1`, opaque UUID IDs, ISO dates/RFC3339 UTC instants, integer Credits (never floats). Request schemas reject unknown fields, including owner_id/price/provider/roles. Server authorizes every object independently of ID opacity. Validations reject client-owned roles and authoritative version/provider labels. Error bodies use `application/problem+json`: type/title/status/code/detail/correlation_id, optional field_errors {field,code}, and optional retry_after_seconds. Detail is safe/localizable, contains no input body, file content or internals; frontend uses stable codes. Errors preserve no private context.

Statuses: 400 invalid JSON/schema/filter/cursor; 401 no authenticated session; 403 role/CSRF/adult/consent/approval forbidden; 404 inaccessible/missing resource (except explicit admin private-library denial is 403+audit); 409 stale resource/version/idempotency or insufficient Credits; 413 body/file bound; 415 unsupported content; 422 accepted syntax but invalid domain evidence/content; 429 local/global quota with Retry-After; 503 unavailable approved route/scanner/budget meter/feature gate. A 503 never selects a paid provider. Owner operation poll returns 200 with state and reason_code even if deferred/reconciling. Shared Problem response schema in OpenAPI deliberately permits these varying HTTP statuses.

All protected endpoints require active session; student endpoints also verified email, adult eligibility and lifecycle permission. All unsafe methods, including login, require Django CSRF cookie + `X-CSRFToken` and matching trusted Origin/Referer. Session expired → 401, CSRF invalid → 403, no side effect. GET/HEAD have no domain mutations except CSRF token issuance. Same-origin credentials; no wildcard credentialed CORS. Session is host-only Secure HttpOnly SameSite=Lax; CSRF token bootstrapped through `/session/csrf`, not URL. Login rotates session and CSRF; logout flushes session; neither is accepted without CSRF. OAuth signup/linking and Admin MFA are specified in identity-and-extension-contracts.md; deployment client IDs/redirects/factor backend are externally configured, never guessed. Cookie-free extension token exchange is the sole explicit unsafe CSRF exception: it rejects cookies and requires a session-approved one-use code, PKCE S256 and exact extension origin. All other unsafe cookie routes retain CSRF.

## Pagination, filtering, concurrency

ASSUMPTION list page limit 20 default, 100 maximum; opaque authenticated cursor bound to filter/sort hash and direction, without PII; response {items,next_cursor}, stable ordering `published_at desc,id desc` or explicit allowed `deadline asc,id asc`. No arbitrary ORM sort/filter fields. Scholarship filters: q (max 200 chars), country (ISO alpha-2), study_level (opaque taxonomy ID, max 64 chars), discipline, funding, language, deadline_before, search_mode and sort. Eligibility/application_state are personalized and require verified active adult ownership before filtering; unknown query keys reject. SEMANTIC applies only the documented approved domain-expansion policy, no hidden provider egress. Taxonomy values use the approved versioned catalog dictionary; validate against configured catalog, never invent enums. Unconfirmed deadlines exclude timed comparisons, not silently treated as far-future. Unknown query keys yield 400. Deleted/changed catalog can alter subsequent pages; cursor is not a database snapshot promise. Owned/admin routes always scope before pagination.

Mutating versioned resources use `If-Match` with server-issued opaque ETag: missing → 428, mismatch → 412 (more specific than generic 409 stale version). Draft schemas requiring snapshots use body version fields with 409 on stale snapshot. Server-side prices require known policy; unknown quote rejects rather than generates free AI. Publish records a new immutable approved version and audit; a race never loses intervening corrections.

`Idempotency-Key` required for operation creation, upload initiation/completion and publication; 16–128 characters from `[A-Za-z0-9._~-]`, scoped by authenticated actor + route + target. Canonical validated body and relevant If-Match hashed; same key/same hash returns original response+resource (202 replay does not enqueue again); changed hash → 409 IDEMPOTENCY_CONFLICT. DB uniqueness and concurrent key locking required. Failures before any side effect need not bind the key; after durable mutation it must stay bound. Reauthorize replays; never replay private output to a now unauthorized actor. Tombstone/operation uniqueness retained for lifecycle of irreversible actions; retention policy cannot enable old-key double debit. Temporary upload key expiry returns existing expired session, not a new storage grant. Transport retry does not settle a second credit.

## Complete selected-Beta wire surface

The [command catalog](command-catalog.md) is generated from the actual OpenAPI operations and supplies request/success DTO, actor proof, CSRF/idempotency/If-Match and source/gate for each operation. It includes registration/verification/Google/linking/MFA/session, profile/consents/recovery, catalog/moderation/reports, free eligibility and quoted AI operations, wallet, private files/documents/versions/approval/restore/export, applications/checklists/history, inbox/preferences, six-state support/assigned shares/SLA, scoped policies/limits/prices/weights/calendar/recovery, aggregate audit and optional extension pairing/data release. DTO properties are strict; semantic ownership/current-policy/flow checks still apply.

Anonymous auth-entry idempotency keys are scoped by pre-auth session+route+target, never globally replayed registration responses. Profile and consent edits require aggregate ETag, application nested mutations require application ETag, policy creation requires current policy-head ETag. Published exact scholarship version is explicit in PublishRequest. Signed quote and manifest commitment are validated before reservation; output language independent of UI. No user role/owner/price/provider labels are accepted as authoritative; Admin typed policy values are permitted only with exact scope/independent gate checks.

New REST routes for future paid transfers/packages are intentionally not activated or speculated without G-PAID. Original Advanced MVP requirements/ACs remain in the matrix/backlog. Ordinary Admin cannot create processor/legal approvals via an arbitrary settings endpoint. Exact compulsory academic fields/rating scale and legal envelope are configured, audited and fail closed where missing, rather than silent contract inventions.

## Result access and client behavior

Operation {id,state,kind,created_at,price_credits,policy_version,result_id?,reason_code?}; result_id nullable, only available on SETTLED. File {id,state,declared_size,created_at}; no direct storage key in normal file read. UploadSession and DownloadCapability contain expiring bearer URLs only in authorized no-store responses; OpenAPI marks them sensitive. No polling provider direct from browser. Duplicate transport retries reuse key; poll with bounded backoff, stop on final status, RECONCILING explains unresolved state. Workers returning valid-looking but ungrounded output yield rejected/reconciling status, not billable success.

## Required implementation acceptance

Schema conformance plus object-level authorization and CSRF are separate tests. Prove public catalog excludes candidates; unauthorized owned ID → 404; admin library → 403+audit; assigned attachment only; cookie/CSRF/origin failure has no mutation; tampered price/owner/provider rejected; repeated identical key returns same reservation; different payload same key conflicts; caps include concurrent reservations; wrong-version file scan/publish cannot accept; timezone day boundary and current consent checked at dispatch/finalization. These are test obligations, not passed tests.
