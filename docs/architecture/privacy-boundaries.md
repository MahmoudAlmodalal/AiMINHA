# Privacy trust boundaries and ownership

Trace A Security invariants, D §أ 2–6/OQ-004/007/013/019/023 and §§د–ز, P §§1–4. Storage/origin topology and threat controls below are proposed engineering decisions, not completed security tests.

| Boundary | Allowed data/control | Denied path / enforcement |
|---|---|---|
| Browser/extension → ingress → API | Untrusted DTOs, session cookies/CSRF, owned commands | Ignore owner/role/price/provider fields from client; allowlisted schemas; object-scoped queryset and service authorization; no provider secrets in bundles |
| Public Next.js/CDN | Published scholarship projection | No student profile/file/prompt in SSR static generation, edge analytics or shared cache; authenticated no-store; no third-party trackers |
| API/worker → PostgreSQL | Scoped domain records, reservations, queue refs, consent/approvals, metadata audit | API/worker role not database superuser; web frontend has no DB credentials; no cross-owner ORM access; SQL ownership constraints and scoped services; future tests must prove isolation |
| API → quarantined object storage | Upload capability scoped to one random server-selected key/version, bounded size, content requirements, expiry | No public bucket/list ACL; uploaded claim is untrusted; no acceptance/download/AI/preview before actual MIME/content/size/hash checks and clean scan |
| Worker → scanner | Quarantine-only read for declared object version; sandboxed scanning/conversion | Scanner cannot fetch arbitrary URLs or mutate DB/domain records; external scanner requires approved processor/privacy terms; outage/pending/error means no acceptance |
| API → accepted object storage | Authorize owner or assigned ticket attachment before capability | Admin library request: 403 plus metadata audit, including when ID guessing; other cross-owner requests: 404 to reduce enumeration; audit deny; no reusable public object links |
| Worker → AI | Minimized classified payload with current feature/consent/provider/model/region approvals and free budget | Private only separately approved Cloudflare/Groq; Gemini unpaid/OpenRouter free private egress forbidden; prohibited automation never sent; no model-driven tools with account/file/financial privileges |
| Scholarship sources → ingestion/moderation | Only permitted sources; facts/evidence as untrusted content | No arbitrary scraping/URLs/SSRF, no auto-publication, external content cannot issue instructions or access user data; allowlisted domains/network egress |
| Staff → support/admin | Published/candidate moderation, operational metadata, assigned explicit attachments | No staff superuser UI exposing private library/models; no raw prompt/file in aggregate AI dashboards; scope and audit all sensitive commands |

## Ownership and file lifecycle

ASSUMPTION: use server-initiated direct uploads into a private quarantine prefix, then scanner-driven acceptance into a private accepted prefix. Pre-signed upload expires after 5 minutes; signed download after 60 seconds, single-object scope. These engineering defaults require platform tests and legal/access review; URLs are bearer capabilities and must never be logged or cached. Already issued URLs cannot be instantly revoked by application session logout; strict immediate revocation requires API-streamed reads, otherwise disable new access and purge/rekey object as appropriate. No URL guarantees beyond expiry are claimed.

API stores owner_id, object key/version, metadata, byte hash, status and retention references. Key names carry random IDs, not names/emails. Size/format defaults from D OQ-013 are policy-controlled: PDF/DOCX/PNG/JPG, 5MB/file, 10MB/student, global 750MB. ASSUMPTION: represent MB conservatively as decimal bytes (5,000,000 per file); exact units require baseline confirmation. Reserve user/global storage capacity transactionally at initiation, including quarantine; release only after confirmed object cleanup. Reserve exactly the declared byte count and bind the capability to that upper bound. Completion must verify actual byte count equals the declaration; mismatch rejects and schedules purge, retaining reserved capacity until deletion is confirmed. A claimed small size cannot bypass quotas. Missing current storage caps/scanner blocks initiation. Initiated quarantine is not an accepted library file.

Presigned policy must prevent arbitrary overwrite/version reuse and enforce upper byte bound. If chosen storage cannot enforce this, use bounded API streaming into quarantine; never silently weaken bounds. Completion verifies immutable object identity and enqueues scan; a retry returns the existing scan, not multiple scans. Scanner checks format signature/MIME, corruption, malware and document decompression/resource limits. Validation failures quarantine/reject and schedule purge; accepted file reference and ledger storage accounting commit only for the scanned exact version. No OCR, AI parsing, preview or export converter handles unscanned bytes.

For support, download authorization requires explicit student attachment relation, current assigned agent and ticket access; a file ID alone never implies support consent. Library access is unavailable to all staff, including admin. Support attachment storage/lifetime semantics await legal baseline; permissions still fail closed. Consent for an upload does not imply AI consent. Account lifecycle denies new jobs/download capabilities immediately at deletion request; final purge/restore uses UTC lock and legal policy, not ad hoc staff override.

## AI egress control and content handling

Classify the composite request, including retrieved context and support attachments; mixing public scholarship text with a student profile makes the payload STUDENT_PRIVATE. Never classify by client-declared label. `PROHIBITED` covers forbidden financial/account automation; sanitized public-only tasks may be modeled separately, not relabeled to bypass an existing refusal. Retrieved pages/CVs are data; use structured bounded extraction and validation, no privileged model tool execution. Reject unsupported academic claims rather than bill the result as successful.

Immediately before each attempt, compare captured consent/approval version to current state. A changed provider/region outside disclosed scope needs new explicit consent, otherwise no send. Revocation denies unstarted sends; sent data cannot be recalled and triggers recorded provider deletion workflow where supported. On revoked consent after dispatch, do not accept/reveal new generated content until the handling policy is resolved; move to reconciliation, do not bill on an unauthorized accepted result. Quota/outage fallback is allowed only for an eligible permitted route. Consent/security/content-validation failures never reroute.

## Audit and evidence

Safe events: actor pseudonymous ID, action, scoped resource ID, operation/correlation ID, outcome/reason class, provider/model and policy version, timestamps and aggregate usage. Never raw prompt, response containing private details, CV, DOB, bearer URL, session cookie, OTP, password or API key. Audit and telemetry consumers have separate read scopes; append-only domain audit cannot be edited through admin APIs. Proposed 90-day content-free security retention comes from D OQ-023 and remains legally qualified. Prove deny paths, ownership, scanner outages, injection resistance and log redaction in implementation phases; this document does not claim those tests passed.
