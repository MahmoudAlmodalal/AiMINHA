## Trusted caller and result types

`ActorContext {principal_id, formal_role:STUDENT|ADMIN, capabilities, session_proof, mfa_proof?, correlation_id}` comes from server-authenticated identity, never request JSON/owner GUC. Public principal receives published projection only. A Student principal must be active/verified/adult. An Admin capability does not imply student-library access or legal/processor approval. Worker context is typed `JobCapability {owner_id,job_id,resource_kind,resource_id,lease_token,scope,input_version_refs}` established by claim routine, not arbitrary owner impersonation. Extension context is audience/portal/selected-resource constrained, no account/status/finance writes.

Commands return `Success<DTO,ETag>` or typed Problem `{code,status,correlation_id,field_errors?,retry_after?}`; unsafe cookie calls require CSRF, command dedupe, and expected ETag where specified. DTO identifiers are references, never authorization. All timestamps UTC with explicit calendar zone where needed. Content-bearing outputs are owner-protected/no-store; operational outputs contain allowlisted metadata only.

## Typed policy and facts semantics

Profile base dictionary covers source identity/contact/name, nationality/residency, academic stage/field/institution/qualification, GPA+known scale, languages/proofs, preferred countries/interests/optional achievements. Missing values remain Unknown, not zero/false. Scalar/list/structured GPA/language values have field-specific schemas and bounded lengths; field keys must exist in approved dictionary, no arbitrary JSON/system instructions. Exact stage compulsory fields and unsupported scales remain G-PROFILE; manual known facts continue, affected eligibility/drafting denies or qualifies missing inputs. Extracted source IDs resolve to same-owner accepted extraction and input manifest; client confirmation never manufactures a new academic fact silently.

Service prices: immutable rows for four documents, extraction, matching rationale and explicitly free support. Funded services price>0; free support zero/chargeable=false; missing quote is not free. Limits use nonnegative integers and admission predicate (not resetting buckets on version change). Weights are five sourced evidence domains, nonnegative basis points summing 10,000 and configured coverage threshold; cannot override mandatory criteria. SLA calendar requires valid IANA zone/0=Monday weekday list/valid local opens<closes/holiday dates, all four priority targets, warnings within target and explicit internal escalation route; no unstated staffing guarantee. Recovery type is positive days/zone/algorithm/legal envelope/effective timestamp in ADR0008. Freeze each applicable snapshot; current flag/revocation checks still apply.

Semantic search baseline is PostgreSQL text ranking plus versioned Admin-curated domain synonyms/taxonomy/intent expansion for bilingual scholarship terms. Return applied mode, expansion policy and limitations; unknown/unsupported semantic mode must explicitly report unavailable or opt-in text fallback, never pretend plain text was semantic. No model egress or vector DB is required by this choice. Any future approved embedding route must separately pass classification/consent/free-quota/quality gates, including anonymous-query privacy and operation ownership, before activation. We do not create a fake student/system account for public AI billing.

## Atomic cross-module orchestration

Admission: trusted caller/current gates → canonical request/quote/snapshots → lock student/global/provider/storage buckets as applicable → one operation/hold/counters/job/audit/outbox → commit 202. Stable hash/key replays existing authorized result, altered body conflicts; no fresh quote/day/price on replay. Physical provider allowance is allocated only immediately before intent/egress, separately from logical Credits.

Acceptance: current fence and lifecycle/consent/processor permission → exact winning call SUCCEEDED → validated grounded result and immutable document if relevant → one debit/terminal witness/counter conversion/job completion/audit/outbox in one commit. Large bytes are staged privately outside locks, counted and unservable until accepted pointer. No valid saved result means no debit; rollback cannot leave accepted generated content. Student approval is a later separate action, not an AI-written approval.

Restore/purge/config change: lock canonical user/request and current policy head in fixed order, record immutable cutoff at confirmation; later Admin setting changes never touch that request. Use R22 canonical lifecycle→consent/policy heads→budgets→operation→wallet/hold→job/result/aggregate order, sorted IDs. Revocation commands enqueue cancellation without reverse-lock walking; no external I/O under locks. Domain ownership does not prevent one orchestrator calling public services under a shared transaction.

Events are metadata envelopes `{event_id,type,schema_version,occurred_at,owner_ref?,entity_id,entity_version,correlation_id}`. Types include OperationAccepted/DocumentSaved/FileAccepted/ScholarshipPublished/DeadlineVersionChanged/ConsentRevoked/AccountDeletionRequested/RecoveryPolicyPublished/TicketHumanRequested/SlaThresholdReached. No bodies/tokens. Consumers dedupe event ID with their effect and reauthorize typed targets; platform outbox cannot impersonate students. Worker/scan/notification/runtime proofs remain NOT RUN in this documentation phase.
