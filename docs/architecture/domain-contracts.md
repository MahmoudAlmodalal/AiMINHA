# Domain module public contracts

Status: PROPOSED engineering contracts (ASSUMPTION), traced to A/D/P in `system-overview.md`; MISSING PRD/phase 01. Shared Django deployment and PostgreSQL database; modules own tables and expose services/DTOs, not their ORM objects. No other module mutates an owner's tables. The orchestration layer calls public services under a shared transaction for atomic cross-module commits. HTTP endpoints call domain services; admin and worker use the same authorization/invariant paths.

## Caller context

Every public service receives `ActorContext {actor_id, actor_kind, scopes, session_id?, correlation_id}` from trusted identity middleware, never request JSON. Worker context adds operation_id, owner_id, lease_token and source policy versions; it confers only that job's rights, not global user impersonation. Authorization always rechecks current lifecycle/ownership. An admin role alone cannot grant private-file, private-AI or cost-policy approvals.

## Atomic orchestration and events

`request_generation` transaction: authorize/snapshot, claim idempotency record, reserve Credits and global logical operation slot, create operation+job+audit; commit before 202. Missing policy/provider approval rejects before reservation. Claiming physical provider budget happens just before egress, since quotas can change after enqueue.

`validate_and_save` transaction: verify current lease token and acceptance/lifecycle gate; insert immutable result (unique operation result); settle through credits service; complete job and append outbox/audit. Any failure rolls everything back. A valid provider response without accepted persisted result never causes a debit. Large objects are staged outside this transaction and inaccessible until an accepted database pointer commits; orphan cleanup is recoverable.

Proposed outbox events: `OperationAccepted`, `DocumentSaved`, `FileAccepted`, `ScholarshipPublished`, `DeadlineVersionChanged`, `ConsentRevoked`, `AccountDeletionRequested`. Each has event_id/type/schema_version/occurred_at/entity_id/entity_version/owner_ref/correlation_id, with no content bodies. At-least-once delivery; consumers deduplicate event_id, then enforce current permissions. These are internal contracts, not a new public streaming API. Fixed resource lock order: actor/lifecycle → daily budget → operation → credit wallet/reservation → job/result; ordered IDs for multi-resource locks. Never call external services under database locks.

Exact account deletion cascade, application transition matrix, consent UI, admin scope provisioning and signup/OAuth linkage workflows are baseline/next-phase inputs. Do not invent those here. Public contracts do not grant implementations freedom to bypass the table ownership or source invariants.
