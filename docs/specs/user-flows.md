## Cross-journey recovery contract

On 401 remove protected content and send to R06 with a safe destination. On 403 do not retry with broader credentials; explain verification, permission or unavailable approval using safe codes. Cross-owner 404 reveals no object existence; Admin library denial remains explicit 403 plus audit. 412/428 require fresh resource/ETag and a visible comparison before resubmission. 409 operation replay/conflict preserves original operation identity. 429 shows server retry interval and manual alternatives; 503 explains affected capability without a paid upsell. Network loss during mutation is **outcome unknown**, not failure: reconnect, recover authoritative state using the same idempotency key, never automatically create a second job/grant/submission. FR-006/049/074–077/109/123–125; NFR-003/008/019/020.

If a full reload loses the in-memory request key before any operation ID was received, the current API has no operation-list/recovery lookup. Explain that recovery is unavailable and offer human support; do not issue another paid request with a new key or claim the first did not run. A future durable recovery design requires separately approved contracts and privacy handling (UX-API-03).

No authenticated offline persistence, background mutation replay, analytics payload containing student text, or public-cache rendering of private pages. Public navigation can remain usable offline with an explicit cached-as-of label if a later implementation approves that cache policy; this phase assumes only already-rendered public data. On logout/lifecycle denial clear private DOM and in-memory content. Before any gated action show reason and next step adjacent to its disabled CTA, with Arabic/English copy in the design system.
