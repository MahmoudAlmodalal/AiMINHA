## Integration failure investigated in this phase

The earlier Phase06 intermittent HTTP500 recurred during Phase07's first combined
run at sign-in and once in a diagnostic run at deletion impact. Metadata showed
Next's rewrite proxy returning HTML500 after upstream `ECONNRESET`/socket hang-up;
Django did not receive the failed request or raise an application exception.
This narrows the observation; it does not establish an upstream library defect's
complete cause.

To make this phase's local/CI integration reliable, local Make/dev/smoke commands
now use Django `--nothreading`, which emits explicit upstream Connection:close.
No identity/privacy domain behavior or prior phase outcome was changed. The
catalog smoke verifies the actual backend Connection:close header and50
consecutive requests; three subsequent identity flows and catalog HTTP smoke
passed. This is a bounded local development-server workaround, not production
server/load certification or a claim to have fixed every pooled-proxy failure.
Historical Phase06 evidence remains unchanged. CI now exercises this workaround.
