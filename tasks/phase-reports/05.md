## PostgreSQL/tooling blocker and dependency provenance

Docker/Compose, daemon and socket are unavailable. `psql`16.15 is present; server binaries were initially absent. Official Ubuntu PostgreSQL16.15, libxml2 and ICU packages were downloaded/extracted only under `/tmp/minhaai-phase05-postgres`, without modifying system package installations. Native initialization failed (exit1) on a 56-byte System V allocation. Retrying the exact command below with mmap also failed (exit1):

```sh
runuser -u nobody -- env LD_LIBRARY_PATH=/tmp/minhaai-phase05-postgres/root/usr/lib/aarch64-linux-gnu /tmp/minhaai-phase05-postgres/root/usr/lib/postgresql/16/bin/initdb -D /tmp/minhaai-phase05-postgres/data -U minhaai --pwfile=/tmp/minhaai-phase05-postgres/password --auth-host=scram-sha-256 --auth-local=peer --no-locale --encoding=UTF8 -c shared_memory_type=mmap -c dynamic_shared_memory_type=mmap
```

Observed error: `could not create shared memory segment: Input/output error`, `shmget(... size=56 ...)`. A minimal direct shmget probe also returned errno5 for root and nobody. The first initialization attempt omitted the two `-c` options and failed identically. PostgreSQL still requires a small System V region with its normal mmap configuration ([official kernel-resource documentation](https://www.postgresql.org/docs/16/kernel-resources.html)). This is an unresolved host capability, not successful database readiness.

Python direct installation from `apps/api/requirements.in` completed (exit0). pip-tools7.6.2's compile attempt hit a `files.pythonhosted.org` read timeout (exit1); hash-generation and a longer-timeout retry were intentionally terminated. The final 28 exact version pins were captured from the successfully installed dependency closure using `importlib.metadata` and PEP508 marker/extra evaluation. Every selected installed version was checked against its dependency specifier; compiler-only packages were excluded. This is a version lock, not a wheel-hash lock. Installation from the pin file and `pip check` validate that fallback; future updates use the documented standard pip-compile workflow.

npm emits an upstream ESLint9.39.1 peer deprecation from Next's import/React/accessibility plugins. The configured CLI is ESLint10.12.0 and lint passes; this development dependency warning remains for upstream peer support review. No dependency-security/production-readiness certification is claimed.
