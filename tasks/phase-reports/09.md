The journal is append-only. Posted balance equals its signed total; active
holds, including reconciliation, equal reserved balance. Available balance is
posted minus reserved and cannot be negative. Release removes a hold without a
positive refund entry. Midnight and elapsed time never refill or expire credits.
Student spending includes settled plus reserved amounts in the captured Hebron
day. Release updates that original day. Global logical admissions include failed
operations and are never refunded or recounted on a retry. Using Hebron for the
global day is an explicit derived assumption, not separately sourced timezone
approval.

The local-only synthetic port creates opaque server fixtures; it accepts only
the exact owned `{"fixture_id":"<UUID>","result":"SYNTHETIC_OK"}` payload.
Validation, saved output, debit, terminal witness, hold/day/wallet changes and
audit commit together. An invalid or unsaved output cannot settle. SQL enforces
immutable identities/history and deferred journal/day/output/finalization
conservation across every participating table; services enforce current account,
lease time and worker fence. No provider is called under locks or elsewhere.

Known synchronous synthetic failure releases once. Uncertainty or expiry keeps
the hold in RECONCILING; no reconciliation exit or automatic resend is enabled
without a future authoritative recovery adapter. At exactly15 minutes the scan
may mark uncertainty. The experimental24-hour target is measured from the first
reconciliation marker, an explicit engineering time basis; passing it only shows
an overdue indication. The command defaults to inspection and `--apply` performs
idempotent markers. It is recoverable by scanning persisted operations again;
there is no external work/outbox or installed production scheduler in this phase.
