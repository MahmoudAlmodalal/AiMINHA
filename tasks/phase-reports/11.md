## Delivered behavior

- `private_files` extends the existing `privacy.PrivateAsset` ownership and
  ticket-share projections. Bounded memory-only multipart ingress prevents an
  oversized file reaching Django's temporary disk handler. Measured decimal caps
  are 5,000,000 bytes/object, 10,000,000/owner, 750,000,000/global. Decimal MB is the
  pre-existing R16 engineering assumption, not a newly invented product decision.
- Quarantine/export allocations count before writes. The single-host adapter uses
  random immutable exact keys, nonoverwriting mode0600 objects, private mode0700
  roots, symlink/public-root rejection and per-object OS fencing. Unknown cleanup
  retains allocation. A five-minute immutable lease and `recover_private_files`
  clean abandoned inactive attempts; active writers are skipped. A delayed writer
  rechecks terminal state under the same fence and cannot recreate purged bytes.
  Asset object key equals actual storage key, preserving purge snapshot identity.
- Actual ClamAV INSTREAM with fresh version evidence is mandatory before file
  acceptance; no permissive scanner flag or client scan-success claim exists.
  Accepted exact hash/size/key and immutable CLEAN receipt are SQL-bound. Structural
  parsing follows scanning: bounded valid PDF/Word OPC/image content, not extension
  or claimed MIME alone. Encryption, active/external content, malformed packages,
  traversal/XXE/macros/OLE, expansion bombs and unsafe subsets fail closed.
- Owner/session-bound60-second grants are rechecked at byte delivery. Account,
  session, expiry, exact object and support assignment/share/MFA revocation during
  I/O deny delivery. Admin cannot browse the private library. Support can read only
  explicitly attached currently assigned ticket files. No public/static byte URL
  exists; sensitive responses are no-store and audits exclude file content/tokens.
- `documents` and `/{locale}/documents` implement verified-adult manual CV,
  motivation letter, personal statement and essay content; independent Arabic or
  English output; escaped previews; immutable versions and hashes; exact owner
  approval; comparison and restore-as-new. Technical validation never marks a
  document approved. Commands use strict DTOs, CSRF, owner filters and revision CAS.
- Local usable PDF/DOCX rendering feeds the same mandatory scanner/storage boundary.
  Canonical rendering and immutable owner/key/version/format export intents recover
  failures after storage success. Re-export reuses the exact saved version without
  an AI operation or debit. Failed rendering/storage/scanning/finalization preserves
  saved source and approval. Ordinary deletion of retained derivative exports is
  protected; uploaded-file deletion releases space only after confirmed cleanup.
- Private extraction/generation endpoints validate eligibility, ownership and
  explicit consent, then safely refuse the unavailable private processing pipeline
  with manual alternatives. No actual CV/profile is sent to any AI processor.
- A distinctly server-only LOCAL fixture accepts no private input/evidence. It
  captures kind/language/idempotency, reserves existing Credits, validates fixed
  literal synthetic facts, saves an immutable document or untrusted extraction
  proposal, and settles once. New SQL witnesses require the artifact **before**
  the old synthetic credit output/debit. The old synthetic validator was not
  weakened. Fake GPA/jobs/awards/provider-success fields cannot save or charge.
  Known local failure releases once; uncertain/crashed outcomes retain holds in
  RECONCILING. Extracted proposals never silently become trusted profile values.
- An internal immutable approved-version submission snapshot primitive is provided.
  No public caller can invent a submitted application. Phase12 must supply the
  authoritative owned application/student-confirmed submission binding. Existing
  ticket access projections are reused without implementing Phase13 lifecycle/SLA.

## Failures found and corrected

- Independent review reproduced non-deterministic DOCX timestamps blocking recovery
  after storage success. Canonical ZIP/core metadata and crash/replay tests fixed it.
- Orphan reservations after process death gained bounded physically fenced cleanup
  and real PostgreSQL concurrent quota regressions. Cleanup failure keeps space held.
- Trailing newlines/CR handling and highly compressible valid text export issues
  were corrected; saved versions remain intact and safe rendered containers parse.
- A fake three-part DOCX package was initially structurally accepted. Valid OPC
  namespaces/content-types/main relationship/Word body plus independent parsing and
  adversarial valid-container fixtures now reject it.
- Export deletion could leave immutable references unusable; retained derivatives
  are now protected rather than silently replaced or recharged.
- First migration attempts during parallel app creation encountered incomplete
  modules; initial new SQL needed CASE parentheses. Final fresh test/smoke migrations
  passed. Schema component-name warnings were corrected before contract generation.
- Initial npm install used inherited Node24; final install/checks use required Node22.
  An exploratory EICAR marker inside a PDF comment was not detected by ClamAV; that
  failed assertion was not called a pass. Reliable raw EICAR and DOCX-member tests
  prove the actual scanner rejects known signatures, not universal malware detection.
