  hours; future policy edits never move a confirmed deletion deadline.

  This conservative safety assumption is not a legal DOB/age verification claim.
- Trust receipt is server proof acceptance after the canonical-account lock,
  not a client timestamp or a promise to honor pre-lock network arrival time.

Implemented `identity` and `privacy` modules provide:

- Canonical UUID account, case-insensitive unique email/provider-subject constraints,
  Django password hashing/validation, explicit adult DOB on signup and rechecked
  activation/login, one-use purpose-bound digest challenges, throttling and safe
  generic registration/recovery acknowledgment. No client-supplied owner/role,
  verified/adult/MFA flag is accepted.
- Verification/resend, login/logout, password reset, tracked cookie sessions,
  rotation,24h inactivity/7d absolute defaults, epoch/all-session invalidation,
  five-minute session-bound password reauthentication and strict CSRF including
  anonymous unsafe routes. Browser storage receives no persistent bearer token.
- Optional Google PKCE/state/nonce and maintained OIDC signature/issuer/audience/
  expiry verification. LINK requires a current adult account and recent password
  proof; SIGN_IN resolves an already linked subject. Email alone never merges
  accounts. Missing configuration returns503. New Google-only signup is not enabled.
- Separate purpose/disclosure/version consent, explicit GRANT/REVOKE, stale ETag/
  snapshot rejection, append-only history. Deletion revokes personal-AI consent;
  restore does not regrant it. Consent alone never approves a processor. No AI call.
- Current deletion-impact review, exact immutable policy snapshot, legal-envelope
  gate, explicit confirmation/reauthentication, immediate access revocation,
  independent recovery email proof, strict `< restore_until`, no session/grant on
  restore, and serialized restore/purge planning.
- Owner-only file metadata and minimal ticket-assignment/exact-share projections.
  Staff library list/read is always403, including Admin. Support needs current
  assignment, server SUPPORT scope/MFA, exact explicit active share, accepted
  asset and active owner. Revocation/reassignment/deletion blocks subsequent reads.
  No object key/version, bytes or signed URL is returned from these endpoints.
- Privacy audit metadata only. Success audit commits atomically; request denials
  audit after service rollback; audit failure denies access. PostgreSQL triggers
  protect audit/consent/disclosure/policy history, deletion snapshot/transitions,
  cross-owner share FKs, object identity and exact purge target identity.
- Durable unique file-purge task records after the stored deadline. Tasks retain
  exact immutable object identity and stay `BLOCKED_STORAGE`. Planner is dry-run
  by default; explicit enqueue cannot erase objects or claim erasure success.
- Arabic/English `/ar/account` and `/en/account` signup/verification/login/reset/
  recovery/consent/link/deletion forms, generated typed runtime contracts/client,
  no-store same-origin requests, safe localized errors and current deletion period.

No scholarship data/API, credit grant/ledger, AI gateway, uploads/scanning/storage
adapter, support workflow/assignment UI, extension, physical purge or deployment
was implemented. `PublicCatalogRead` is a tested anonymous safe-read permission
